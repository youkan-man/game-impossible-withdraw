# 8重の退会ロック / 0.2

## 変わらない境界

PC内の架空ブラウザ、古物店の経営、CC、Bot、15階層のパンくずは維持する。元の赤い「いいえ」・灰色の「はい（蝿）」・3つのチェックは第1層。最後のチェックも「デポジットを譲渡します」のまま。

入場デポジットは1回だけ。層の追加や差し戻しで再徴収しない。罠の多くは残り時間や手続き進行を奪う。失敗時の損失は既に預けた額の範囲内で、店・商品・Bot・所持金全額を奪わない。現実のメール、契約、サイト、口座には一切アクセスしない。

## 層と状態遷移

`入口 → 封印 → 本人 → 決裁 → 意思 → 署名 → 審査 → 本送信 → 規約改訂`

### 1. 表の退会ページ

従来のチェック、画像認証、閲覧規約、逃げるボタンをすべて処理して初めて第2層へ進む。`submit()`はこの層しか処理できず、呼び続けても後続の層を飛ばせない。通過後はこの層のチェックや広告が後続の画面に干渉しない。

### 2. 順序式の多重封印

月・星・鍵、周回後は花・傘を含む3〜5個の封印。挑戦ごとに開錠順を決定し画面に表示する。順序違反は全施錠と0.9秒減少。「一括解除」は全施錠と1.2秒減少。開錠後3.5秒放置すると直前の封印が戻る。

手続きBot Lv5で順番を自動処理。監査Bot Lv4または「封印の逆止弁」でバネによる再施錠を停止。順序違反までは保護しない。

### 3. 期限付き本人認証

6桁コードはゲーム内受信箱に発行する。コードは先頭ゼロを含む文字列で比較。初回の有効時間は7秒、周回に応じて最短4秒。再送ごとに以前と異なるコードを発行して、前のコードを即時失効させ、0.3秒を消費する。旧メールは最大4件まで表示し、旧版と明示する。誤コードは0.8秒、期限切れは0.6秒減る。

受信箱には「会員継続のご確認」の承認ボタンも存在する。押すとコードが無効になり、本人認証からやり直し、1.5秒減少。

手続きBot Lv6で取得・入力。監査Bot Lv5で発行するコードの有効時間+7秒。「認証コード延命」はレベルごとに+5秒、最大3レベル。

### 4. 部署決裁・原本照合

本人確認課・意思確認課・預託精算課の順を挑戦ごとに決める。各部署は前部署の承認を要求する。順序違反は0.8秒減少で、既に得た印は維持する。

画面上部に現行原本のIDを表示する一方、最初の添付書類では旧原本のコピーを「推奨」とする。現行IDを選び直して申請する。旧原本は本人認証へ差し戻し、1.3秒減少。「迅速審査」は本人認証へ差し戻し、1.5秒減少。

手続きBot Lv7で原本と決裁順を確認。「原本の公証」または監査Bot Lv6なら差し戻しは現在の層に留める。

### 5. 取消の取消の確認

3回、周回後は最大6回の意味確認。取消・不同意の撤回・取り下げない意思など、否定文を重ねる。選択肢の順も変わるが、各画面には意味を判断できる補足説明を置く。「退会を続ける」という意味の回答を選ぶと進行。

誤答は決裁層へ差し戻し、1.2秒減少。公証・監査Lv6がある場合は意思確認層の最初に戻る。手続きBot Lv8は意味を判定して進む。

### 6. 動的規約・署名同期

規約は初期6秒間隔、周回後は最短3.6秒間隔で自動改訂される。版を取り込み、会員継続・デポジット譲渡・本送信保留の3つの同意をすべて外し、照合語を入力して署名する。

改訂されると取り込み済み版が無効になり、3つのチェックが復活する。同じ照合語でも古い版の署名は無効。版違い・残存同意は0.7秒、照合語違いは0.5秒減少。「常に最新版に合わせる」も改訂を発生させ、0.5秒減少。

手続きBot Lv9で一連の操作を自動化。監査Bot Lv7か「規約版のピン留め」で自動改訂を止める。ただし手動で最新版への同期を要求すると改訂される。

### 7. 審査待ち・受付時刻

受付番号を発行して3人待ちから開始、周回で最大8人。1秒に1人ずつ進む。自分の順番になると4秒周期の最初1.5秒だけ受付窓が開く。「受付優先権」はレベルごとに待ち人数を1人減らし、窓を0.4秒延長する。

待ち時間中や閉じた窓への送信は0.5秒減少。再申請は最後尾+1人へ戻して0.8秒減少。**ゲーム内ブラウザの再読込ボタン**は番号を破棄し、1秒減少する。通常のアプリ再起動ではセーブに残った番号を復元する。

手続きBot Lv10は時刻を見て送信。監査Bot Lv8は順番到来後の受付窓を常時開放するが、順番自体は飛ばさない。

### 8. 偽の完了・最終送信

受付完了・99.9%という見た目の画面。ただし「完了して閉じる」は会員継続を確定して挑戦を終了する。元の預託精算規則が適用され、退会突破には数えない。監査Bot Lv9があればこの偽ボタンを阻止する。

「処理明細」を開き、まだ残っている会員継続への同意を解除する。本送信ボタンを1.4秒、周回後は最大2秒押し続ける。ポインターとEnter / Spaceに対応。途中解除、フォーカス喪失、ブラウザ非表示、ゲーム内タブ切替で手動の長押しは破棄。進行は継ぎ足せない。

手続きBot Lv11で明細と継続同意を処理、Lv12で本送信。Botを停止するとBot由来の長押しも停止する。本送信時に前の7層すべての承認を再確認する。

## 前進を残す、差し戻しを罠にする

初めて層0〜6を通過すると8秒と解析1を加える。「引継ぎ時間の交渉」は追加時間をレベルごとに2秒増加、最大3レベル。時間と解析の付与履歴は挑戦ごとに保持し、差し戻された層を何度通過しても再取得できない。CCの返還も最終精算の1回だけ。

差し戻しは現在の承認を失効させるが、解析と一度獲得した突破実績は残す。どこで止まったか、誤操作・差し戻し回数、現行の原本・規約版を画面で追えるようにする。タイマーを進める操作はゲーム状態側で検証し、見た目のdisabled属性だけに依存しない。

## 保存・移行

保存キーとversion=1を維持し、旧データに`attempt.labyrinth`がない場合だけ入口状態を追加する。入場済みデポジットや残り時間をリセット・再徴収しない。日時や経過時間の小数精度を保持する。全層のコード・決裁・チェック・待ち番号を復元できる。

物理的な押下状態はロード時に破棄する。Bot由来もいったん破棄し、現時点で稼働しているBotが通常の自動化ルートから再開する。壊れた層番号、飛ばされた承認、順序不正の印、不正な時刻・認証配列は復元時に拒否する。

## テスト

`npm test` は既存の経済・預託・保存の回帰テストと、新しい層ごとの単体テストを実行する。`tests/labyrinth-fixture.cjs` は通常のゲームAPIだけを使って途中状態を作るテスト専用品であり、配信HTMLに含めない。

`tests/labyrinth_ui.py` は手動8層通過、Bot通過、偽ボタン、コード失効、原本差し戻し、規約改訂、審査窓、短押しと長押し、フォーカス・タブ切替、390/768/1920pxを確認する。`--in-memory`ではHTMLをChromiumへ直接渡し保存領域をアダプターに置き換えるため、実HTTPナビゲーションやディスク永続化・Docker起動の確認とは区別する。
