# ゲーム設計

## コンセプト

退会はしたい。だが退会ページを開くためにはお金が必要。そのお金を稼ぐには、退会したいサイトで商売を大きくしなくてはならない。

手続き側は理不尽、経営側は予測可能にする。失敗の範囲は事前に示すデポジットに限定し、商品やBotの永久喪失は設けない。失敗にも解析データという進行を与える。退会成立ではなく、最後の規約改訂を繰り返すエンドレス進行を採用する。

## 二つのループ

### お店

仕入れ → 在庫 → 出品 → 販売完了 → CC → 商品・棚・Bot。

初期資金1,200 CC、保管数8。時計・カメラ・ラジオ・ランプ・レコード・携帯ゲーム機が初期商品。販売実績5/12/25/45件でタイプライター、ヘッドホン、レンズ、レコードプレーヤー、シンセサイザー、腕時計が解放される。

市場は30秒で更新。仕入れ価格は基準価格 × [0.77,1.21)、在庫は2〜4個。シード付き乱数を使い、次の更新まで価格を固定する。出品済み商品の価格も変更しない。

| 方針 | 標準価格に対する倍率 | 標準販売時間に対する倍率 |
| --- | ---: | ---: |
| 薄利多売 | 0.83 | 0.6 |
| 標準価格 | 1 | 1 |
| じっくり高値 | 1.35 | 1.9 |

販売価格 = 四捨五入(商品基準価格 × 方針倍率 × (1 + 目利きレベル × 0.08) × (1 + 規約周回数 × 0.12))。

販売速度 = 1 + 有効な接客Botレベル × 0.22。

出品Botの間隔 = 7 / (1 + (レベル − 1) × 0.36) 秒。仕入れBotは分子11秒。買付候補は解放済み・在庫あり・保管可能・運転資金を残せる・利益が正の商品のみ。その中で見込み利益 / 標準販売時間の大きいものを選ぶ。

棚の容量 = 8 + 棚レベル × 4。拡張費用 = 四捨五入(300 × 1.7^棚レベル)。棚レベル最大12。資金ゼロ救済は5秒の梱包バイトで40 CC。連打による即時受取はできない。

### 退会

15階層の探索 → デポジット確認 → 退会ページ → 妨害 → 失敗 / 最終確認突破 → 解析 → Bot・研究 → 再挑戦。

導線は HOME → マイページ → 設定 → その他 → お得情報 → キャンペーン → ソフトクリーム → 味 → ミックス → 退会希望 → 退会要望 → 退会要請 → 味 → 抹茶 → 退会ページ。

デポジット = 四捨五入(500 × (1 + floor(過去の挑戦数 / 4) × 0.2) × (1 + 規約周回数 × 0.65) × (1 − 交渉術レベル × 0.1))。

入場は常に明示操作。直接URL風の表示やブックマーク・画面一覧からは預託を迂回できない。入場時に所持金から引いて`attempt.deposit`へ分離する。終了時は最初に`attempt`を解除し、その後に返還することで二重精算を防ぐ。

| 結果 | 返還 |
| --- | --- |
| 譲渡チェックが残っている失敗 | 監査Botの保護率 |
| 譲渡チェックを外した失敗 | 55%と監査Botの保護率の高い方 |
| 最終確認の突破 | 80% |

監査Bot保護率 = min(80%, レベル × 12%)。没収 = 預託額 − 返還額。「蝿プラン」の見せかけの料金も預託額の範囲内で精算し、所持金全額や後日の実課金には波及しない。

失敗・突破ごとに1 + floor(手続き進行度 / 2) の解析データ。突破時はさらに3。新しく発見した妨害ごとに1。進行度はロック解除・チェック解除・認証・規約同意から得られる。チェック復活を何度も解除すると、その分も解析対象になる。

## 妨害と対抗策

| 妨害 | 実装 | 対抗 |
| --- | --- | --- |
| 強制ログアウト | 入場後2秒、実時間で終了 | 延長Botでレベルごとに3秒追加 |
| チェックロック | 3項目を最初は解除不可 | 無料の講座、手続きBot |
| チェック復活 | 3秒ごとに「永久に退会しません」を再チェック | 固定パッチまたは監査Bot Lv2 |
| はい（蝿） | 偽の選択で手続き失敗 | 正規の下部フォームを使う |
| 広告 | 4秒経過で出現。偽の×は0.6秒を奪う | 小さな本物の閉じる、監査Bot Lv3、手続きBot Lv3 |
| 抹茶認証 | 9枚の中から3枚を選択。誤答で0.7秒減る | 手動認証、手続きBot Lv2 |
| 閲覧規約 | 末尾に到達して初めて同意可能 | スクロール、手続きBot Lv3 |
| 逃げる確定ボタン | 最大5回、3位置の間を移動 | 繰り返し操作、監査Bot Lv1 |
| 規約改訂 | 最終確認後も退会は成立せず次の周回へ | 店とBotの強化を継続 |

講座・ゲーム内別タブ・ブラウザ最小化・ブラウザタブ非表示でも時計は止まらない。入力の正当性はシミュレーション側でも検証する。キーボードやタッチでも逃走回数を消化できるため、ポインター専用の操作にはしない。画面全体やOSのカーソルそのものを奪う機能は実装しない。

## 保存・時間

ランタイムに外部依存は持たず、ゲーム状態を各端末のlocalStorageに保存する。通貨は整数、上限1兆CC。セーブの日時は通貨とは別の上限を使い、ミリ秒のUNIX時刻を保持する。

保存はチェックサム付きエンベロープ。前回の有効セーブをバックアップとして残す。JSONの読み込みでは形式、フィールド、配列長、通貨範囲、商品ID、認証情報を検証する。破損した原本を有効なバックアップの上へコピーしない。

通常は100msごとに実経過時間を与え、離席復帰も同じシミュレーション関数を使う。捕捉時間は最大2時間。退会中は最大0.1秒、経営のみでは最大1秒刻みで処理するため、長時間離席の売買タイミングにはサブ秒の丸め差がある。退会中に閉じても、復帰時に残時間を精算する。

同一オリジンのタブ間では有効期限付きのプレイ権を使い、他タブでは時間経過・操作・保存を止める。これはシングルプレイヤー向けの重複実行抑止であり、セーブ改造を防ぐ認証基盤やマルチプレイヤー用の排他制御ではない。

## 実装の境界

- `game.js` は純粋な状態遷移。DOM、ストレージ、ネットワークに触れない。
- `save.js` は保存のエンコードと検証。テスト用Storageで故障経路を再現できる。
- `app.js` は表示と入力の調整、保存と時間の供給。ゲームの通貨操作は原則シミュレーションを通す。
- SVG商品図は同梱コードで描画する。画像CDN・実サイトのスクレイピング・ユーザー情報の送信は行わない。

本バージョンは遊べる初期実装。経済の長期的な爽快感・難易度曲線・妨害のバリエーションは継続調整の対象とする。
