# 退会できません。 / IMPOSSIBLE WITHDRAW

**店をたたむために、店を大きくする。**

PCのデスクトップ上で架空のブラウザを操作する、古物売買 × 自動化 × 退会妨害のインクリメンタルゲームです。CCはゲーム内通貨「チャッピーコイン」。実際のECサイト、送金、契約、アカウント操作には接続しません。

## 起動

```sh
docker compose up --build -d
```

ブラウザで `http://localhost:8080` を開きます。サーバーにプレイヤーのデータは保存しません。同じURLを使う別のプレイヤーとは進行状況を共有しません。

Dockerを使わず、`index.html` を直接開くこともできます。ローカル配信なら次のコマンドだけで動きます。

```sh
python3 -m http.server 8080
```

ネット接続もビルドも不要な**単体HTML**を生成する場合：

```sh
python3 tools/bundle.py
# dist/impossible-withdraw.html を開く
```

実行時の外部ライブラリ・外部フォント・外部画像はありません。Dockerイメージ取得時や開発用ツールの導入時には別途接続が必要です。

## 遊び方

1. **仕入れ市場**で古物を買う。初期資金は1,200 CC。市場は30秒ごとに再入荷・再価格設定されます。
2. **自分の店**で出品する。時間経過で売れ、代金は自動で入金されます。薄利多売・標準・高値の3方針を選べます。
3. **Botラボ**で自動仕入れ・出品・接客を導入し、商売を拡大する。販売実績に応じて高額商品が解放されます。
4. **退会手続き**の15階層をたどり、デポジットを預けて退会ページに入場する。最初はたった2秒です。
5. 失敗と新しい妨害の発見で**解析データ**を集める。研究と退会用Botで対抗する。
6. 最終確認を突破すると**規約改訂**が発生。退会は成立せず、値上がりした販売価格と新しいデポジットで次の周回へ進みます。

資金を使い切っても、店の「梱包バイト」で5秒ごとに40 CCを稼いで再出発できます。無制限の無料コイン補充や本番用のチート画面はありません。

## Bot

| Bot | 初期価格 | 自動化・効果 |
| --- | ---: | --- |
| 出品Bot | 260 CC | 在庫を自動出品。強化で処理間隔短縮。 |
| 仕入れBot | 620 CC | 利益と販売時間を比較して買付。設定した運転資金を必ず残す。 |
| 接客Bot | 900 CC | レベルごとに販売速度 +22%。 |
| 延長Bot | 1,100 CC | 次回入場の制限時間をレベルごとに +3秒。 |
| 手続きBot | 1,600 CC | ページ移動・ロック・チェック。Lv2で画像認証、Lv3で規約と広告、Lv4で送信。 |
| 監査Bot | 2,300 CC | 没収額の一部を保護。Lv1で逃げるボタン、Lv2で再チェック、Lv3で広告を阻止。 |

各Botは最大Lv12。購入・強化はCCを使い、停止中は効果も止まります。強化価格は初期価格 × 1.72^現在レベル。手続きBotは**入場デポジットを勝手に支払いません**。

## デポジットと妨害

退会ページは、元の赤い「いいえ」・灰色の「はい（蝿）」・長いパンくずを踏襲しています。「全財産を譲渡します」は**「デポジットを譲渡します」**に変更しました。

預託額は所持金から分離します。失敗で失うのは預託したCCのみ。譲渡チェックを外せば55%を返還し、監査Botの保護率がそれより高ければ高い方を適用します。保護率は1レベルにつき12%、最大80%。重複精算・二重返還はしません。

妨害は、2秒の強制ログアウト、外せないチェック、3秒ごとの再チェック、偽の「はい」、閉じるほど時間を奪う広告、抹茶とわさびの画像認証、末尾まで読ませる規約、逃げる確定ボタン、最後の規約改訂。講座や別タブを開いても制限時間は進みます。

通常の退会フォームは最後まで退会させてくれません。**退会成立のエンディングではなく、妨害を突破して規約を周回するエンドレス型**です。お店・商品・Botは没収されません。

詳しい式と実装方針は [docs/DESIGN.md](docs/DESIGN.md) に記載しています。

## 操作と保存

ブラウザのタブ、戻る・進む、最小化・復帰・最大化、タイトルバーのドラッグ、商品・在庫・Botの右クリックメニューを使用できます。架空のアドレス欄はゲーム内表示です。

5秒ごと／主要操作後のローカル保存と直前バックアップを実装。読み込み時にチェックサムとデータ形式を検証します。片方が破損した場合はバックアップから復元し、両方が破損した場合は警告して元データを保持します。保存不可の環境でもメモリ上で動作し、警告を表示します。

設定からJSONを書き出し・読み込みできます。別端末への移動やブラウザデータ削除前に書き出してください。離席中は最大2時間、前景と同じ売買・妨害ルールを計算します。同一オリジンの複数タブではプレイ権を1タブに限定し、二重シミュレーションを避けます。ブラウザの保存領域の削除やプライベートモードを越えて保持される保証はありません。

## 開発・検証

```sh
npm test        # Nodeの組み込みテストランナー。npm install不要
npm run check   # JavaScriptの構文確認
npm run build   # Python 3で単体HTMLを生成
```

UIテストにはPythonのPlaywrightとChromiumが必要です。

```sh
python3 -m pip install -r tests/requirements.txt
python3 -m playwright install chromium
# 別ターミナルで python3 -m http.server 8080
python3 tests/ui_smoke.py
```

URLにアクセスできない検証環境では、HTMLをメモリ上へ直接読み込むモードもあります。

```sh
python3 tests/ui_smoke.py --in-memory --chromium /usr/bin/chromium
```

このモードでは`about:blank`に永続オリジンがないためStorageをテスト用アダプターに置き換えます。保存・復元・破損・容量エラーはNodeテストで別途検証します。実ブラウザのディスク永続化やDocker起動の検証を代替するものではありません。

スクリーンショットと結果は`test-artifacts/`に出力します。通常画面、15階層、モーダル、退会妨害、手動突破、Botによる突破、390/768/1920pxのレイアウトを検査します。

## ファイル構成

- `game.js`：DOM・保存・外部通信を持たないゲーム状態と時間シミュレーション。
- `save.js`：セーブのエンコード、整合性検証、直前バックアップ。
- `app.js`：デスクトップ、架空ブラウザ、全画面、モーダル、操作、タブ間のプレイ権管理。
- `styles.css`：PCを主対象としたレスポンシブUI。商品イラストはコード内のSVG。
- `tools/bundle.py`：外部依存のない単体HTMLを生成。
- `tests/`：ゲームロジックとPlaywright操作テスト。
